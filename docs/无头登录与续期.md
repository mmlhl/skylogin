# 无头登录与凭证续期

> 面向开发者。用户侧说明见 README 的「记住渠道」「账号与安全」两节。
> 相关结论（什么凭证能免选区）见 [渠道记忆.md](渠道记忆.md)。

## 一、为什么要"无头"

账号密码登录最初是**弹网易自己的登录窗**（子进程加载 `mpay.dll`）。这条路的两个硬伤：

1. **密码在网易窗口里输入**，我们从头到尾看不到明文，所以存不下来，凭证一过期就得让用户重新操作；
2. 用哪个 `game_id` 初始化决定了拿到的凭证身份，而窗口路径很容易被配置带偏，拿到平台身份（a50）凭证后**选渠道永远不生效**。

`mpay.dll` 自己导出了一些不弹窗的接口，其中 `UILessUrsLogin` 能直接完成账号密码登录。
用它之后：密码是我们收的（可以存）、上下文是我们定的（一定是游戏身份）、界面上也不会再冒出
网易的登录窗和"记住的账号"列表。

## 二、三个层次

```
① 业务层  internal/app/headless.go
     HeadlessPasswordLogin / HeadlessTokenLogin / HeadlessListAccounts
     HeadlessLoginAccount（登录 + 落库 + 存密码）
     autoRelogin / autoReloginAndVerify（自动重登）

② 子进程  cmd/skylogin --headless-login
     stdin: 请求 JSON（含密码，不进命令行）
     --out: 结果 JSON

③ DLL 层  internal/mpayhost/api.go
     LoginByPassword / LoginByToken / LoginByTicket / SetPlatform / ListAccounts
```

为什么中间要隔一层子进程：`mpay.dll` 的窗口、消息循环、接口实例必须绑在同一个
OS 线程上，登录异常时还可能直接把进程带走。放子进程里，崩了只崩子进程，主界面还在
（和官方登录窗的进程模型一致）。

### 参数包装

| 场景 | 调用 | 关键参数 |
|---|---|---|
| 账号密码登录 | `HeadlessPasswordLogin(user, pass, gameID)` | `gameID` 传 `profile.LongGameID` 拿游戏身份，传 `profile.HostedGameID` 拿平台身份 |
| 已有凭证登录 | `HeadlessTokenLogin(user, token, device, gameID)` | `device` 必须和 token 配套 |
| 读记住的账号 | `HeadlessListAccounts()` | — |
| 添加/更新账号 | `HeadlessLoginAccount(user, pass, region, name)` | 成功即落库并保存密码 |
| 写平台记录 | `mpayhost.SetPlatform(...)` | 平台侧记录，**游戏不读，不是免选区解法** |

HTTP：`POST /api/accounts/headless-login`
```json
{"user":"…","password":"…","region":"android","name":""}
```

## 三、凭证身份由上下文决定

| init 的 game_id | 拿到的 `g_i` | 能启动游戏 | 能按渠道签发 |
|---|---|---|---|
| `…-g-ma75` | 游戏 | ✅ | ✅ |
| `…-g-a50` | 平台 | ✅ | ❌ 501 |

所以正常流程一律用 `…-g-ma75`。`mpayDebugGameID()` 已经写死游戏身份，
只有显式设环境变量 `SKYLOGIN_MPAY_GAME=a50` 才会复现平台身份。

## 四、续期规则

| 凭证等级 | 寿命 | 处理 |
|---|---|---|
| `sa=-9` 账号级（密码 / 验证码） | 长期 | 不动。定期校验，失效则自动重登 |
| `sa=3` 会话级（扫码 / 换票） | 数天~数周 | 每 12 小时滚动一次（签票 → `login/ticket`） |
| `sa=-4` 大神扫码 / 手机号会话 | 未知 | 也滚动：滚完变 `sa=3`，纳入可续期轨道 |

滚动为什么安全：滚动只把 `lt`（登录时间）推到现在，换回来的还是同一个账号、
同一个身份（`g_i` 不变）。`sa=-9` 不滚是因为滚一遍会被降级成会话级。

调度位置：`rollStaleTokens()`（程序启动时后台跑）、`rollAccountToken()`（启动游戏后顺手）。

## 五、自动登录

触发条件（三条同时满足）：

1. 账号是网易官方账号，且有 `MpayToken`；
2. 账号存过密码（`SavedUser` / `SavedPass`，DPAPI 加密）；
3. 定时校验（`credcheck.go`，每 4 小时）发现现有凭证签不出票。

流程：

```
mintTicket 失败
  → autoRelogin：用保存的密码无头登录（游戏身份上下文）
  → saveHeadlessCred：新凭证进 MpayToken，设备号一起换
  → autoReloginAndVerify：用新凭证真的签一次票确认
  → 成功则标记 ok；失败只记日志，不动账号
```

限流：一轮最多自动重登 2 个账号（`maxReloginPerRound`），避免密码本身错了还反复打接口。

**官方登录窗那条路径存不了密码**（密码在网易窗口里），所以这类账号只能手动刷新凭证。
想获得自动重登，用无头登录（`/api/accounts/headless-login`）重新登录一次即可。

## 六、安全

- 密码用 **Windows DPAPI** 加密后存进 `accounts.json`（整份文件本来也是 DPAPI 加密的），
  绑定当前 Windows 用户；拷到别的机器解不开（`accountPassword` 会明确报"换了 Windows 用户？"）。
- 密码只走**子进程 stdin**，不进命令行、不进日志。结果文件落在 `%TEMP%`，读完即删。
- 明文密码只在内存里存活一次登录的时间；RSA 加密由 DLL 的公钥完成。

## 七、实测（2026-11-08 夜）

| 验证 | 结果 |
|---|---|
| 主进程 → 子进程 → DLL 无头登录 | ✅ 3 秒，返回 `g_i=游戏`、326 字符凭证、16 字符票 |
| 无头添加账号 + 落库 + 密码往返 | ✅ `existed=true`、凭证可签发、DPAPI 往返一致 |
| 伪造过期凭证 → 自动重登 → 恢复 | ✅ 3 秒救回，并当场完成一次渠道签发（安卓，16 字符票） |
| `tokenOwner` / `Identity` 身份判定 | ✅ 单元测试覆盖游戏/平台/脏数据 |

## 八、没做的

- 界面入口：接口（`/api/accounts/headless-login`）与前端函数（`api.headlessLogin`）已就绪，
  添加账号弹窗里的表单还没接——需要先确定"让用户在本工具里输网易密码"的产品文案。
- 短信验证码账号没有密码，无法自动重登（验证码是一次性的）。
- 自动重登没有做并发控制：多开同时启动多个失效账号时，会各自起一个子进程。
