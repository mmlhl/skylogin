# 实锤二：临时通行证能自己续期（最关键的一条）

## 用大白话说

临时通行证上写着"从哪天开始"。我们拿它去换一张新的，**开始时间就变成现在了**，
等于有效期重新开始算。

```
旧通行证（开始于 10:00）→ 换张票 → 拿票换新通行证（开始于 11:30）
```

新通行证立刻能用，而且和旧的不一样（是新的一张）。

**所以只要在过期前换一次，就一直有效。** 不用扫码、不用额外账号、每个扫码号都适用。

## 实测数据

同一天对两个号各做过一次，结果一样：

```
旧：开始于 1793879111 → 新：开始于 1793879845   新证能用 ✅
旧：开始于 1793879268 → 新：开始于 1793879919   新证能用 ✅
```

（这两个数字是 Unix 时间戳，差值就是"晚了多久"，说明时间确实推后了。）

## 代码里怎么做的

`internal/app/rolltoken.go`

| 什么时候做 | 做什么 |
|---|---|
| 登录器启动时 | 把"超过 12 小时没换过"的临时通行证换一遍（后台跑，不影响界面） |
| 启动游戏拿到票之后 | 顺手给这个号换一次（一小时内不重复换） |

日志里会看到：

```
acct3：会话凭证已续期（lt 推到现在）
共续期 N 个账号的会话凭证
```

## 重要：长期通行证不能碰

**为什么不能拿长期通行证去做同样的操作？**

因为"拿票换登录"这个动作，本质是"换一次**登录会话**"，它只会给你临时通行证。
拿长期通行证去换，回来的就是临时的——等于**把永久的换成了会过期的**。

实测确认：

```
原来的：sa=-9（长期）   没有开始时间
换完的：sa=3 （临时）   开始于 1793880197
```

所以代码里判断：**没有"开始时间"的（长期通行证）一律跳过，碰都不碰。**

### 好消息：原来那张不会被弄坏

滚完之后立刻检查原来那张：

```
原来那张还在：sa=-9（长期），仍然可用 ✅
```

所以"换"这个动作本身不会毁掉旧凭证，真正的风险是**"把换回来的临时证存回去"**。
代码里两件事都不做，最稳妥。

## 还有一个细节

拿长期通行证签的票，在两个 `a50` 上下文里都被拒绝（`1003 用户请求参数错误`），
只有"光遇本体 jf=ma75"这个上下文能过。这和"上下文要跟着凭证走"的判断一致。

## 技术附录

续期 = 两次请求：

```
1) 签票
GET/POST /mpay/api/users/create_ticket
   （用 token 换一张 AAAA 开头的一次性票）

2) 拿票换登录
POST /mpay/api/users/login/ticket
   （票换回来一个 user.token；这个 token 的 lt 是当前时间）
```

代码入口：

- `tokenLoginUnix(token)`：把凭证里的开始时间解出来（解不出来 = 长期证）
- `rollSessionToken(acc, dev)`：签票 + login/ticket，返回新凭证
- `rollStaleTokens()`：启动时批量续期
- `rollAccountToken(uid)`：单账号续期

提交：`fa555fd`、`d6f8389`、`234434d`
## 密码重登会顶掉旧的临时会话（已验证）

实验：拿一个长期证滚出一条临时会话 → 用密码重新登录同一个号 → 回头看那条会话。

```
【1】密码登录后存回来的：sa=-9（长期证）        ← 又变回长期证了 ✅
【3】现在存的凭证：可用 ✅
【2】密码重登前滚出来的那条临时会话：1306 用户登录失效 ❌   ← 被顶掉了
```

两个结论：

1. **密码登录一定能拿回长期证**，跟签不签发新设备无关
2. **密码登录会把同一个号之前的所有会话顶掉**——包括我们滚动出来的那条

### 这对产品意味着什么

滚动续期有效的前提是：**这个号没有在别处（平台、游戏官网、我们自己的密码登录）
重新登录过**。一旦重登，旧的临时会话立刻失效，下次启动就只能重新扫码。

反过来推：用户扫码号"过几天就失效"，很可能有一部分不是自然过期，
而是他自己在平台或别的地方用这个号登了一次。

### 所以顺序很重要

- 想保住扫码号：别用同一个号去别处登录
- 真要用密码登：登完我们存的就是新的长期证，反而更稳，也不用再滚
## 大神扫码给的也不是长期证（2026-11-05 20:24 实测）

在官方登录窗（游戏那份 mpay.dll 4.20）里改用「大神扫码」扫了一次，回调里的凭证是：

```
sa=-4  lt=1793881485  odi=amawv2yac7ngo6bk
字段: di,fgi,g_i,lt,mps,odi,prs,s,sa,si,t,u,w,wp,wu
```

对照一下三种来源：

| 来源 | sa | 有没有 lt | 判断 |
|---|---|---|---|
| 账号密码（DLL） | **-9** | 没有 | 长期证 |
| 光遇扫码（我们自己的流程） | **3** | 有 | 会话证 |
| **大神扫码（DLL 窗口里）** | **-4** | **有** | **还是会话证** |

所以「大神扫码 = 长期」这个说法**从凭证结构上看不成立**。

它的 sa 值和普通扫码不一样（-4 vs 3），理论上有效期可能更长，
但没跨过时间验过，不能当长期证用。

而且这条 -4 的凭证**一样能滚动续期**（实测）：

```
大神扫来的: sa=-4 lt=1793881485
滚完的:     sa=3  lt=1793881537   新证可用 ✅
```

注意：滚完会变成 sa=3。如果 -4 实际上比 3 活得更久，滚动反而会缩短它——
这一点还没验，等做过"不滚的 -4 到底活多久"再说。
### 补充：又扫了一次，结果一样（2026-11-05 20:29）

三种扫法汇总（同一个号、同一天）：

| 扫法 | 窗口给的二维码 | `sa` | `lt` | 判断 |
|---|---|---|---|---|
| 我们自己的扫码弹窗 | 光遇手游 | 3 | 有 | 会话证 |
| 官方窗口 + a50 | 大神 | -4 | 有 | 会话证 |
| 官方窗口 + ma75 | 光遇手游 | -4 | 有 | 会话证 |

**结论：所有扫码路径拿到的都是会话证，只有密码（和短信）给长期证。**
