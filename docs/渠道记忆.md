# 渠道记忆（免选区）—— 结论、流程与实测记录

> 状态：**结论已定稿**（2026-11-08 夜，ad / ios 两条渠道均实测通过）。
> 适用对象：光·遇 PC（网易官服 `ma75`）。渠道服账号（华为 / B站 / 4399 / vivo / 九游）
> 的渠道由各自 SDK 决定，不适用本机制。

## 一、一句话结论

**免选区要同时满足两个条件：**

1. 凭证是**游戏身份（ma75）**签发的 —— 平台身份（a50）拿去做 `uni_sauth` 会回 501；
2. 凭证是**账号级**（`sa=-9` / `-99`）—— 会话级（`sa=3` / `-4`）能过 `uni_sauth`（200），
   但到 `confirm_login` 会被 403/1306 顶回来，**签不出票**。

满足这两条的只有一种来源：**用账号密码或手机验证码、以游戏身份登录一次**。

平台身份（a50）凭证可以签一张票、再用 `game_id=…-ma75` 兑换出一份游戏凭证，
但兑换出来的**一定是 `sa=3` 会话级**：授权那步能过，确认那步过不去，所以
**不能用来免选区**（4.2 有两次对照实测，包括平台兑换和账号级自己滚出来的 sa=3）。

> 2026-11-09 更正：曾一度认为"`sa=3` 也能选区"、"a50 换证就能选区"，都只验到
> `uni_sauth` 那一步就下了结论。补验 `confirm_login` 后推翻了——**限制在等级本身，
> 不在凭证来源**。

## 二、流程

```
① 准备母凭证：登录得到一份签发身份是游戏（ma75）的 MPay token
     ├─ 账号密码 / 手机验证码：直接用游戏身份登录
     └─ 平台身份（a50）登录的号：签一张票 → 用游戏上下文兑换 → 换出游戏身份 token

② 用户在界面上选渠道：先不选 / 安卓 / iOS（存 Account.Region）

③ 每次启动按渠道签发（不需要重新登录，约 1–2 秒、5 次请求）
     uni_sauth(platform=ad|ios)         ← 选区就落在这一句
     → create_login（a50 平台身份建码，dst_jf_game_id=ma75，qrcode_channel_type=2）
     → scan（服务端回 1424，要求切到 ma75 上下文）
     → confirm_login
     → query → login_info.code
     → ExchangeTicket（匿名换票，不带 sid）
     → 交票给游戏（op14），游戏不弹选区

④ 续期
     sa=-9：账号级，长期有效，无需续期
     sa=3 ：会话级，每 12 小时滚动一次（签票 → login/ticket），滚动后仍是 ma75、仍能选区
     滚动失败 → 提示重新登录，登录后再按当前渠道签发
```

三个必须照抄的细节（改动前先读第 4 节）：

1. `confirm_login` 的外层 `device_id` 必须是**这张 token 签发时的设备号**，否则 `1003 用户请求参数错误`；
2. `confirm_login` 的 `token` 传**原生 `1-eyJ…` 文本**，不能 base64 包装，否则 `1306 用户登录失效`；
3. 建码与换票用的是 **a50 平台设备号**，与第 1 条那个不是同一个，三者不能混用。

## 三、凭证矩阵（全部实测）

| 凭证来源 | `g_i` | `sa` | `uni_sauth` | `confirm` 出票 | 能免选区 |
|---|---|---|---|---|---|
| 账号密码登录（游戏身份） | 游戏 | -9 | 200 | ✅ | ✅ |
| 手机验证码登录 | 游戏 | -99 | 200 | ✅ | ✅ |
| 平台凭证签票 → 游戏上下文兑换 | 游戏 | 3 | 200 | ❌ 1306 | ❌ |
| 账号级自己滚出来的会话凭证 | 游戏 | 3 | 200 | ❌ 1306 | ❌ |
| 扫码（游戏码） | 游戏 | -4 | 未验证 | 未验证 | ❌（真机会弹） |
| 平台身份（a50）直接声明 | 平台 | -9 | ❌ 501 | — | ❌ |

**看这张表记住一句**：`uni_sauth` 200 只代表"授权拿到了"，**不等于免选区**；
真正决定成败的是 `confirm_login` 能不能过，而它只认账号级凭证。

**同一条账号，凭证身份取决于"用哪个 game_id 上下文登录/兑换"，与有没有窗口、
加载哪份 `mpay.dll` 无关。** 这一条是反复踩坑后定下来的：

| 初始化上下文 | 得到 | 结果 |
|---|---|---|
| `…-g-ma75` | `g_i=游戏 sa=-9` | 可签发 |
| `…-g-a50` | `g_i=平台 sa=-9` | 声明被拒 501 |

两种凭证长度都是 326 字符、`sa` 都是 -9，**只有 `g_i` 不同**，日志里看不出来，
必须解 token 才算得清。

## 四、实测记录（2026-11-08 夜）

用项目 `.env` 里的测试账号，全程无头、不落任何明文凭证。

**4.1 凭证身份由初始化上下文决定**

```
平台目录 mpay.dll 4.21 + init …-g-ma75 + UILess 账号密码
  → token g_i=游戏 sa=-9 t=1（配套设备 18 字符）→ 出票 16 字符
同一份 DLL + init …-g-a50
  → token g_i=平台 sa=-9 t=1 → 声明渠道 501
```

**4.2 会话级（sa=3）只能过授权，出不了票**（两次对照）

```
账号级 sa=-9 凭证 → create_ticket → login/ticket(游戏上下文) → sa=3（370 字符）
  → uni_sauth(platform=ad|ios) → 200          ← 授权这步过了
  → create_login → scan → confirm_login → 403 / code=1306   ← 出不了票

平台凭证 → create_ticket → login/ticket(游戏上下文) → sa=3（370 字符）
  → 同样：uni_sauth 200，confirm 1306
```

两次来源不同、结果一致，所以**限制在凭证等级，不在来源**。
另外拿 sa=3 去让 DLL 认（`UILessTokenLogin`）想升级成账号级也失败：回调为空。

**4.3 平台凭证可以换出游戏凭证，但换出来的是 sa=3**

```
平台凭证 g_i=平台 sa=-9
  → create_ticket(平台上下文) → 16 字符票
  → login/ticket(游戏上下文)  → g_i=游戏 sa=3 t=1（370 字符）
  → uni_sauth(platform=ios|ad) → 200     ← 到此为止，签不出票
```

对照：官方平台启动游戏时就是这么做的（抓包 2026-11-08 14:47:18）：

```
POST https://service.mkey.163.com/mpay/api/users/login/ticket
  ticket=AAAA…  game_id=…-g-ma75  device_id=…
→ user.token 解出 {"g_i":"游戏","sa":3,"t":7,"odi":"设备号","si":"会话id"}
```

所以"平台账号能进游戏"并不是平台把身份转给了游戏，而是**票兑换时服务端按请求里的
`game_id` 上下文签发了游戏身份的 token**。平台凭证 → 游戏凭证这条"次级凭证"通道
是官方链路，不需要平台应用的签名密钥。

**4.4 为什么"自动换证"这条路最后被撤掉**

一度把 4.3 做成了自动修复：发现手里是平台凭证，就签票 + 兑换，换出游戏凭证再签发。
用真实的无密码账号跑过，换证确实成功（0.33 秒、370 字符、g_i=ma75），
**但紧接着 confirm_login 报 403/1306，票签不出来**——换出来的永远是 sa=3。

所以现在的自动修复只剩一条：**存过账号密码的账号，自动无头重登**（拿到的直接是
sa=-9）。没密码的号只能提示用户点「刷新凭证」，用密码或验证码重登一次。

`convertPlatformCred` 函数保留下来，但只作诊断用，正式流程不再调用。

## 五、排除项（别再走）

1. **拿平台身份（a50）凭证直接调 `uni_sauth` → 501。**
   `uni_sauth` 的 `X-Client-Sign` 密钥按应用区分；游戏（ma75）的密钥在客户端配置里，
   平台应用的密钥不在（翻过 `cloudRes.json` 的 193 条配置、49 个 game 的 `log_key`，
   没有平台应用那一条）。要拿只能动态分析平台 DLL，成本远高于换票。
2. **平台凭证换证也不能免选区**：换出来的必然是 `sa=3`，`confirm_login` 会 1306
   （4.2 两次对照）。所以"a50 登录的账号想选区"只有一条路——**重新登录一次**
   （密码或验证码，且必须是游戏身份上下文），拿到 `sa=-9`。
3. **平台身份凭证无法直接 `create_ticket` 给游戏用**（跨身份被拒）。

3. **本地库（`unisdk\*-64-mpay.db`）与渠道选择无关**：库里写不进去也读不出来，
   而且实测"库里有记录照样弹选区"。
4. **票本身不带渠道**：`create_ticket` 的参数与官方逐字段一致，一样弹选区；
   差别只在发票前有没有做 `platform` 声明。
5. **`SetUserPlatform` / `UpdateAasAcountPlatform` 不解决问题**：它们写的是平台侧记录，
   游戏不读。可以留着当辅助，不能当解法。

## 七、边界

- 只有**网易官方账号**能选区；渠道服账号接口层直接拒绝。
- `hm`（鸿蒙）：通路已留，**未验证**，界面未暴露。
- 扫码凭证（`sa=-4`）：能否走同一条路、寿命多久，均未验证。
- 切渠道后是**下次启动生效**，没有做运行中热切换。
- 多开并发签发未做限流，每个账号独立签发。
